## Notes on interpretation

- Bits per byte, not loss per token: Telugu costs ~6.0 bytes per token against ~2.8 for English in this tokenizer, so per-token loss would flatter the Indic lane by a factor of two for free.

- The selector reference is trained on `web` and `code` only. That is not a rigged experiment; it is what a proxy direction built from what the model already does well looks like in production.

- Selector overhead here is large relative to a real run because the batches are tiny; the scoring pass is a fixed cost per step that amortises as sequence length and batch size grow.
